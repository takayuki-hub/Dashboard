# TASK-0006: ユーザー操作イベント実装

## タスク概要

### タイトル
ユーザー操作イベント実装

### タイプ
TDD（テスト駆動開発）

### 優先度
High（Phase 2のコアタスク）

### 工数見積もり
8時間

### 依存関係
- **前提タスク**: TASK-0005（画面遷移イベント実装）
- **後続タスク**: TASK-0007（エラートラッキング実装）

### 作業対象モジュール
- `:core:analytics` - ユーザー操作イベント定数追加、パラメータ定数追加
- `:feature:task` - タスク作成・編集・削除イベント
- `:feature:news` - ニュース記事クリックイベント
- `:feature:weather` - 天気データ更新イベント

## 背景・目的

### 解決すべき課題
現在、画面遷移イベントの記録は実装されていますが、ユーザーがアプリ内でどのような操作を行っているかを追跡するユーザー操作イベントが未実装です。ユーザー操作イベントは、機能の利用状況を詳細に分析し、UX改善につなげるために必須です。

🔵 **信頼性レベル**: 青信号（要件定義書 REQ-202、REQ-203、ユーザヒアリング2026-09-12 Q4より確実）

### 達成目標
1. ユーザー操作イベント定数の追加（タスク作成・編集・削除、ニュース記事クリック、天気更新）
2. ユーザー操作パラメータ定数の追加
3. 各ViewModelでのユーザー操作イベント記録
4. イベントパラメータの正確性を保証するテストの作成

### 非目標
- エラートラッキングの実装（TASK-0007で実装）
- カスタムユーザー属性の設定（別タスクで実装）
- A/Bテストイベントの実装

## 要件定義

### 機能要件（EARS記法）

#### 通常要件 - イベント定数管理

**REQ-0006-001**: システムはユーザー操作イベント名を`AnalyticsEvents`オブジェクトに追加しなければならない
🔵 *REQ-202、REQ-203（要件定義書）、ユーザヒアリング2026-09-12 Q4より*

- イベント名定数（追加）:
  - `TASK_CREATE_CLICKED`: タスク作成ボタンクリック
  - `TASK_EDIT_CLICKED`: タスク編集ボタンクリック
  - `TASK_DELETE_CLICKED`: タスク削除ボタンクリック
  - `TASK_COMPLETE_TOGGLED`: タスク完了状態トグル
  - `NEWS_ARTICLE_CLICKED`: ニュース記事クリック
  - `WEATHER_REFRESH_CLICKED`: 天気データ更新ボタンクリック
- Firebase Analytics制限に準拠（最大40文字）🔵 *EDGE-102より*

**REQ-0006-002**: システムはユーザー操作パラメータ名を`AnalyticsParams`オブジェクトに追加しなければならない
🔵 *NFR-201（要件定義書）、コーディングベストプラクティスより*

- パラメータ名定数（追加）:
  - `TASK_ID`: タスクID（一意識別子）
  - `TASK_TITLE`: タスクタイトル
  - `ARTICLE_ID`: 記事ID
  - `ARTICLE_TITLE`: 記事タイトル
  - `ACTION_TYPE`: アクション種別
  - `IS_COMPLETED`: 完了状態（true/false）
- Firebase Analytics制限に準拠（最大40文字）🔵 *EDGE-103より*

#### 通常要件 - タスク操作イベント

  - `TASK_ID`: タスクID

## エッジケース・考慮事項

### エラーハンドリング

#### タスクIDがnull
- **シナリオ**: onTaskEditClicked()やonTaskDeleteClicked()でタスクIDがnullまたは空
- **対応**: メソッド呼び出し前にバリデーション、イベント記録をスキップ
- **影響度**: 中
- **信頼性**: 🟡 エラーハンドリングベストプラクティスより妥当な推測

#### 記事URLが無効
- **シナリオ**: onArticleClicked()で記事URLが空またはnull
- **対応**: hashCode()実行前にnullチェック、デフォルト値設定
- **影響度**: 中
- **信頼性**: 🟡 エラーハンドリングベストプラクティスより妥当な推測

### パフォーマンス考慮事項

#### 高頻度イベント
- **課題**: ユーザーが短時間に多数のタスクを作成・削除した場合のイベント送信負荷
- **対応**: Firebase Analytics SDKが自動的にバッチング処理、デバウンス不要
- **影響度**: 低
- **信頼性**: 🔵 Firebase Analytics SDK仕様より

#### viewModelScope使用
- **課題**: イベント記録がViewModelライフサイクルに依存
- **対応**: viewModelScope.launch使用、ViewModelクリア時に自動キャンセル
- **影響度**: 低
- **信頼性**: 🔵 Android ViewModel仕様より

### セキュリティ考慮事項

#### PII除外確認
- **課題**: タスクタイトル、記事タイトルなどのユーザー生成コンテンツがPIIに該当する可能性
- **対応**: TASK_TITLEやARTICLE_TITLEパラメータを使用せず、IDのみ記録 🔵 *NFR-0006-004より*
- **影響度**: 高

#### URLハッシュ値の一意性
- **課題**: hashCode()の衝突リスク
- **対応**: Firebase Analytics側で統計的に問題なし、完全一意性不要
- **影響度**: 低
- **信頼性**: 🟡 hashCode()仕様から妥当な推測
