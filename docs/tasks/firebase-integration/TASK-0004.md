# TASK-0004: アプリライフサイクルイベント実装

## タスク概要

### タイトル

### 作業対象モジュール
- `:core:analytics` - イベント定数クラス、パラメータ定数クラス
- `:app` - MainApplicationでのFirebase初期化、アプリライフサイクルイベント記録

## 背景・目的

### 解決すべき課題
現在、Firebase Analyticsの基本設定（Google Services Plugin、Firebase BOM、google-services.json）は完了していますが、アプリケーションのライフサイクルイベント（起動、終了）を記録するコードが未実装です。ユーザー行動分析の基盤として、アプリの基本的な利用状況を追跡する必要があります。

🔵 **信頼性レベル**: 青信号（要件定義書 REQ-206、REQ-207、ユーザヒアリング2026-09-12 Q4より確実）

### 達成目標
1. Firebase Analyticsイベント名とパラメータ名を定数で管理
2. MainApplicationでのFirebase明示的初期化
3. アプリ起動イベント（app_open）の記録
4. アプリ終了イベント（app_background）の記録
5. イベント定数の網羅性を保証するテストの作成

### 非目標
- 画面遷移イベントの実装（TASK-0005で実装）
- ユーザー操作イベントの実装（TASK-0006で実装）
- デバッグビルドでのAnalytics無効化（TASK-0003で実装済み想定）

## 要件定義

### 機能要件（EARS記法）

#### 通常要件 - イベント定数管理

**REQ-0004-001**: システムはFirebase Analyticsイベント名を`AnalyticsEvents`オブジェクトで管理しなければならない
🔵 *NFR-201（要件定義書）、コーディングベストプラクティスより*

- イベント名定数:
  - `APP_OPEN`: アプリ起動イベント
  - `APP_BACKGROUND`: アプリ終了イベント
- Firebase Analytics制限に準拠（最大40文字）🔵 *EDGE-102より*

**REQ-0004-002**: システムはFirebase Analyticsパラメータ名を`AnalyticsParams`オブジェクトで管理しなければならない
🔵 *NFR-201（要件定義書）、コーディングベストプラクティスより*

- パラメータ名定数:
  - `TIMESTAMP`: イベント発生時刻
  - `APP_VERSION`: アプリバージョン
- Firebase Analytics制限に準拠（最大40文字）🔵 *EDGE-103より*

#### 通常要件 - Firebase初期化

**REQ-0004-003**: システムはMainApplication.onCreate()でFirebase Analyticsを明示的に初期化しなければならない
🔵 *REQ-001（要件定義書）、ユーザヒアリング2026-09-12 Q5より*

- `FirebaseAnalytics.getInstance(context)`を使用
- デバッグビルドでの無効化設定を適用

#### 通常要件 - アプリ起動イベント

**REQ-0004-004**: システムはMainApplication.onCreate()でアプリ起動イベントを記録しなければならない
🔵 *REQ-206（要件定義書）、ユーザヒアリング2026-09-12 Q4より*

- イベント名: `APP_OPEN`
- パラメータ:
  - `TIMESTAMP`: 起動時刻（ISO 8601形式）
  - `APP_VERSION`: BuildConfig.VERSION_NAME

**REQ-0004-005**: システムはアプリ起動イベント記録がUIスレッドをブロックしてはならない
🟡 *NFR-001（要件定義書）より妥当な推測*

- AnalyticsRepositoryがコルーチンまたは非同期処理を使用

#### 通常要件 - アプリ終了イベント

**REQ-0004-006**: システムはアプリがバックグラウンドに移行したときにアプリ終了イベントを記録しなければならない
🔵 *REQ-207（要件定義書）、ユーザヒアリング2026-09-12 Q4より*

- イベント名: `APP_BACKGROUND`
- パラメータ:
  - `TIMESTAMP`: 終了時刻（ISO 8601形式）
  - `APP_VERSION`: BuildConfig.VERSION_NAME
- `ProcessLifecycleOwner`を使用してアプリライフサイクルを監視

### 制約要件

**REQ-0004-007**: システムはイベント名を最大40文字に制限しなければならない
🔵 *EDGE-102（要件定義書）、Firebase Analytics制限仕様より*

**REQ-0004-008**: システムはパラメータ名を最大40文字に制限しなければならない
🔵 *EDGE-103（要件定義書）、Firebase Analytics制限仕様より*

**REQ-0004-009**: システムは1イベントあたり最大25個のパラメータを記録できなければならない
🔵 *EDGE-101（要件定義書）、Firebase Analytics制限仕様より*

### 非機能要件

#### パフォーマンス

**NFR-0004-001**: システムはAnalyticsイベント記録が500ms以内に完了しなければならない
🟡 *NFR-002（要件定義書）より妥当な推測*

**NFR-0004-002**: システムはAnalyticsイベント記録がUIスレッドをブロックしてはならない
🟡 *NFR-001（要件定義書）より妥当な推測*

#### セキュリティ

**NFR-0004-003**: システムは個人識別情報（PII）をAnalyticsイベントに含めてはならない
🔵 *NFR-101（要件定義書）、Firebase Analyticsセキュリティガイドラインより*

3. **AppLifecycleObserver**

   - 責務: アプリライフサイクルイベントの監視とAnalytics記録

```kotlin
package com.github.takayuki_hub.dashboard.lifecycle

import androidx.lifecycle.DefaultLifecycleObserver
import androidx.lifecycle.LifecycleOwner
import com.github.takayuki_hub.dashboard.BuildConfig
import com.github.takayuki_hub.dashboard.core.analytics.AnalyticsEvents
import com.github.takayuki_hub.dashboard.core.analytics.AnalyticsParams
import com.github.takayuki_hub.dashboard.core.analytics.AnalyticsRepository
import kotlinx.coroutines.CoroutineScope
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.launch
import java.time.Instant
import javax.inject.Inject

/**
 * アプリライフサイクルイベントを監視し、Firebase Analyticsに記録
 */
class AppLifecycleObserver @Inject constructor(
    private val analyticsRepository: AnalyticsRepository
) : DefaultLifecycleObserver {

    private val scope = CoroutineScope(Dispatchers.IO)

    override fun onStart(owner: LifecycleOwner) {
        // アプリがフォアグラウンドに移行
        // 初回起動は MainApplication.onCreate で記録
    }

    override fun onStop(owner: LifecycleOwner) {
        // アプリがバックグラウンドに移行
        scope.launch {
            analyticsRepository.logEvent(
                eventName = AnalyticsEvents.APP_BACKGROUND,
                params = mapOf(
                    AnalyticsParams.TIMESTAMP to Instant.now().toString(),
                    AnalyticsParams.APP_VERSION to BuildConfig.VERSION_NAME
                )
            )
        }
    }
}
```

#### 変更対象ファイル

4. **MainApplication.kt**
   - パス: `app/src/main/java/com/github/takayuki_hub/dashboard/MainApplication.kt`
   - 変更内容:

```kotlin
package com.github.takayuki_hub.dashboard

import android.app.Application
import androidx.lifecycle.ProcessLifecycleOwner
import com.github.takayuki_hub.dashboard.core.analytics.AnalyticsEvents
import com.github.takayuki_hub.dashboard.core.analytics.AnalyticsParams
import com.github.takayuki_hub.dashboard.core.analytics.AnalyticsRepository
import com.github.takayuki_hub.dashboard.lifecycle.AppLifecycleObserver
import com.google.firebase.analytics.FirebaseAnalytics
import dagger.hilt.android.HiltAndroidApp
import kotlinx.coroutines.CoroutineScope
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.launch
import java.time.Instant
import javax.inject.Inject

@HiltAndroidApp
class MainApplication : Application() {

    @Inject
    lateinit var analyticsRepository: AnalyticsRepository

    @Inject
    lateinit var appLifecycleObserver: AppLifecycleObserver

    override fun onCreate() {
        super.onCreate()

        // Firebase Analytics 明示的初期化
        FirebaseAnalytics.getInstance(this)

        // アプリライフサイクルオブザーバー登録
        ProcessLifecycleOwner.get().lifecycle.addObserver(appLifecycleObserver)

        // アプリ起動イベント記録
        CoroutineScope(Dispatchers.IO).launch {
            analyticsRepository.logEvent(
                eventName = AnalyticsEvents.APP_OPEN,
                params = mapOf(
                    AnalyticsParams.TIMESTAMP to Instant.now().toString(),
                    AnalyticsParams.APP_VERSION to BuildConfig.VERSION_NAME
                )
            )
        }
    }
}
```

## エッジケース・考慮事項

### エラーハンドリング

#### AnalyticsRepository未初期化
- **シナリオ**: MainApplication.onCreate()でAnalyticsRepositoryがまだ注入されていない
- **対応**: Hiltのフィールドインジェクションは`super.onCreate()`後に完了するため、順序を正しく保つ
- **影響度**: 高
- **信頼性**: 🔵 Hilt仕様より

#### ProcessLifecycleOwner未利用可能
- **シナリオ**: Android API 24でProcessLifecycleOwnerが利用できない可能性
- **対応**: Lifecycle KTX 2.8.5は互換性あり、Min SDK 24でも動作
- **影響度**: 低
- **信頼性**: 🔵 AndroidX Lifecycle仕様より

### パフォーマンス考慮事項

#### イベント記録のスレッド管理
- **課題**: MainApplication.onCreate()はメインスレッドで実行される
- **対応**: CoroutineScope(Dispatchers.IO)で非同期実行 🟡 *NFR-0004-002より*
- **影響度**: 中

#### タイムスタンプフォーマット
- **課題**: Instant.now().toString()はISO 8601形式、パース可能性確保
- **対応**: 標準フォーマット使用
- **影響度**: 低

### セキュリティ考慮事項

#### PII除外確認
- **課題**: TIMESTAMPとAPP_VERSIONにPIIが含まれないことを確認
- **対応**: 両方とも非PII 🔵 *NFR-0004-003より*
- **影響度**: 高
