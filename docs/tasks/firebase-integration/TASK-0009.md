#### 1. MainApplication.kt（デバッグ設定）
**ファイルパス**: `/Users/takayuki/AndroidStudioProjects/Dashboard/app/src/main/java/com/github/takayuki_hub/dashboard/MainApplication.kt`

**現状**:

**変更内容**:
```kotlin
@HiltAndroidApp
class MainApplication : Application() {

    @Inject
    lateinit var firebaseAnalytics: FirebaseAnalytics

    @Inject
    lateinit var analyticsRepository: AnalyticsRepository

    override fun onCreate() {
        super.onCreate()

        // デバッグビルド時はFirebase Analyticsを無効化
        configureAnalytics()

        // ユーザープロパティの設定
        setUserProperties()
    }

    private fun configureAnalytics() {
        if (BuildConfig.DEBUG) {
            firebaseAnalytics.setAnalyticsCollectionEnabled(false)
            android.util.Log.d(
                TAG,
                "Firebase Analytics disabled in debug build"
            )
        } else {
            firebaseAnalytics.setAnalyticsCollectionEnabled(true)
            android.util.Log.d(
                TAG,
                "Firebase Analytics enabled in release build"
            )
        }
    }

    private fun setUserProperties() {
        // アプリバージョンを設定
        val appVersion = BuildConfig.VERSION_NAME
        firebaseAnalytics.setUserProperty("app_version", appVersion)

        // 初回起動時刻の設定（SharedPreferencesで管理）
        val sharedPrefs = getSharedPreferences("analytics_prefs", Context.MODE_PRIVATE)
        val firstOpenTime = sharedPrefs.getLong("first_open_time", 0L)

        if (firstOpenTime == 0L) {
            val currentTime = System.currentTimeMillis()
            sharedPrefs.edit()
                .putLong("first_open_time", currentTime)
                .apply()
            firebaseAnalytics.setUserProperty(
                "first_open_time",
                currentTime.toString()
            )
            android.util.Log.d(TAG, "First open time set: $currentTime")
        } else {
            firebaseAnalytics.setUserProperty(
                "first_open_time",
                firstOpenTime.toString()
            )
        }
    }

    companion object {
        private const val TAG = "MainApplication"
    }
}
```

**追加実装**:
```kotlin
@Singleton
class AnalyticsRepositoryImpl @Inject constructor(
    private val firebaseAnalytics: FirebaseAnalytics
) : AnalyticsRepository {

    // 既存のメソッド...

    override suspend fun setUserProperty(name: String, value: String) {
        withContext(Dispatchers.IO) {
            firebaseAnalytics.setUserProperty(name, value)
            android.util.Log.d(TAG, "User property set: $name = $value")
        }
    }

    override suspend fun setUserProperties(properties: Map<String, String>) {
        withContext(Dispatchers.IO) {
            properties.forEach { (name, value) ->
                firebaseAnalytics.setUserProperty(name, value)
            }
            android.util.Log.d(TAG, "User properties set: ${properties.size} properties")
        }
    }

    companion object {
        private const val TAG = "AnalyticsRepositoryImpl"
    }
}
```

# Firebase Analytics DebugView 有効化手順

## 概要
Firebase Analytics DebugViewを使用すると、リアルタイムでAnalyticsイベントを確認できます。

## 有効化手順

### Android デバイスの場合

1. デバイスをUSB接続
2. 以下のコマンドを実行:
   ```bash
   adb shell setprop debug.firebase.analytics.app com.github.takayuki_hub.dashboard
   ```

### 無効化手順

DebugViewを無効化する場合:
```bash
adb shell setprop debug.firebase.analytics.app .none.
```

## DebugViewの確認

1. [Firebase Console](https://console.firebase.google.com/)にアクセス
2. プロジェクト「dashboard-2fcc1」を選択
3. 左メニューから「Analytics」→「DebugView」を選択
4. アプリを操作すると、リアルタイムでイベントが表示される

## 注意事項

- デバッグビルドではAnalyticsが無効化されているため、DebugViewを使用する場合は`BuildConfig.DEBUG`の分岐をコメントアウトするか、リリースビルドを使用してください
- デバイス再起動後は、再度`adb shell setprop`コマンドを実行する必要があります

## リスクと対策

### リスク1: BuildConfig.DEBUGのモック化が困難 🟡
**影響度**: 中
**発生確率**: 中

**対策**:
- Robolectric使用でBuildConfigをテスト環境で制御
- 必要に応じて、デバッグフラグを依存性注入で提供する設計に変更
- インストルメンテーションテストで実機確認

**信頼性**: 🟡 *テスト実装経験から推測*

---

### リスク2: ユーザープロパティの永続化が期待通り動作しない 🟡
**影響度**: 低
**発生確率**: 低

**対策**:
- Firebase Analytics SDKが内部でユーザープロパティを永続化する
- SharedPreferencesで初回起動時刻を管理し、明示的に永続化
- Firebase Console で実際のユーザープロパティを確認

**信頼性**: 🟡 *Firebase Analytics仕様から推測*

---

### リスク3: Dispatchers.IOのテストが複雑 🟡
**影響度**: 中
**発生確率**: 中

**対策**:
- `kotlinx-coroutines-test`の`StandardTestDispatcher`を使用
- `advanceUntilIdle()`で非同期処理を同期的にテスト
- MockKの`coVerify`を使用して`suspend`関数を検証

**信頼性**: 🟡 *Coroutinesテストベストプラクティスから推測*
