#### 1.1 `AnalyticsModule.kt` の作成

**ファイルパス**: `core/analytics/src/main/java/com/github/takayuki_hub/dashboard/core/analytics/di/AnalyticsModule.kt`

```kotlin
package com.github.takayuki_hub.dashboard.core.analytics.di

import android.content.Context
import com.github.takayuki_hub.dashboard.core.analytics.repository.AnalyticsRepository
import com.github.takayuki_hub.dashboard.core.analytics.repository.AnalyticsRepositoryImpl
import com.google.firebase.analytics.FirebaseAnalytics
import com.google.firebase.analytics.ktx.analytics
import com.google.firebase.ktx.Firebase
import dagger.Binds
import dagger.Module
import dagger.Provides
import dagger.hilt.InstallIn
import dagger.hilt.android.qualifiers.ApplicationContext
import dagger.hilt.components.SingletonComponent
import javax.inject.Singleton

/**
 * Firebase Analyticsの依存性注入モジュール
 *
 * このモジュールは、FirebaseAnalyticsインスタンスとAnalyticsRepositoryを
 * アプリケーション全体で使用できるように提供します。
 */
@Module
@InstallIn(SingletonComponent::class)
object AnalyticsModule {

    /**
     * FirebaseAnalyticsインスタンスを提供する
     *
     * @param context アプリケーションコンテキスト
     * @return FirebaseAnalyticsインスタンス
     */
    @Provides
    @Singleton
    fun provideFirebaseAnalytics(
        @ApplicationContext context: Context
    ): FirebaseAnalytics {
        return Firebase.analytics
    }
}

/**
 * AnalyticsRepositoryのバインディングモジュール
 */
@Module
@InstallIn(SingletonComponent::class)
interface AnalyticsRepositoryModule {

    /**
     * AnalyticsRepositoryImplをAnalyticsRepositoryとしてバインドする
     *
     * @param impl AnalyticsRepositoryの実装
     * @return AnalyticsRepositoryインターフェース
     */
    @Binds
    @Singleton
    fun bindAnalyticsRepository(
        impl: AnalyticsRepositoryImpl
    ): AnalyticsRepository
}
```

## 技術的注意事項

### Hilt DIパターン

#### @Provides vs @Binds

- **@Provides**: 外部ライブラリ（Firebase Analyticsなど）のインスタンス提供に使用
- **@Binds**: 自作インターフェースの実装クラスをバインドする際に使用

#### Singleton スコープ

`@Singleton`アノテーションを使用することで、アプリケーションライフサイクル全体で単一のインスタンスが保持されます。

#### InstallIn

`@InstallIn(SingletonComponent::class)`により、このモジュールがアプリケーション全体で使用可能になります。

### Firebase KTX

Firebase KTX（Kotlin Extensions）を使用することで、以下の利点があります：

- Kotlin Coroutines対応
- より簡潔なコード
- Kotlin慣用的なAPI

### デバッグビルドでの無効化

デバッグビルドでAnalyticsを無効化することで、開発中のテストデータが本番データに混入することを防ぎます。

### BuildConfig

`buildFeatures { buildConfig = true }`を設定することで、ビルド構成に応じた定数を`BuildConfig`クラスで使用できます。

### KSP生成コード

Hiltは**KSP（Kotlin Symbol Processing）**を使用してコード生成を行います。以下の場合にKSP生成コードのエラーが発生する可能性があります：

- 新しいHiltモジュールを追加した場合
- `@Inject`アノテーションを追加した場合
- Hilt関連のアノテーションを変更した場合

**対処法**: `./gradlew kspDebugKotlin`を実行

## トラブルシューティング

### 想定される問題と対処法

#### 1. Hiltコード生成エラー

**問題**: `@HiltAndroidApp`や`@AndroidEntryPoint`が認識されない
**対処法**:
1. `./gradlew clean`を実行
2. `./gradlew kspDebugKotlin`を実行
3. Android Studioを再起動

#### 2. FirebaseAnalyticsインジェクションエラー

**問題**: `FirebaseAnalytics`がインジェクトされない
**対処法**:
1. `Firebase.analytics`の代わりに`FirebaseAnalytics.getInstance(context)`を使用
2. `google-services.json`が正しく配置されているか確認

#### 3. ビルドConfigエラー

**問題**: `BuildConfig.ENABLE_ANALYTICS`が認識されない
**対処法**:
1. `buildFeatures { buildConfig = true }`が設定されているか確認
2. `./gradlew clean && ./gradlew assembleDebug`を実行

#### 4. 循環依存エラー

**問題**: Hiltモジュール間で循環依存が発生
**対処法**:
1. モジュール構成を見直す
2. `@Provides`と`@Binds`を別々のモジュールに分離

#### 5. Firebase初期化エラー

**問題**: アプリ起動時に`FirebaseApp`が初期化されていない
**対処法**:
1. `google-services.json`が`app/`ディレクトリに配置されているか確認
2. `com.google.gms.google-services`プラグインが適用されているか確認
