## 背景・目的

### 解決すべき課題
現在、アプリケーション内で発生するエラーや例外を追跡する仕組みが未実装です。エラートラッキングは、アプリケーションの品質向上とユーザー体験改善に不可欠です。特に、ネットワークエラー、データベースエラー、予期しない例外を適切に記録し、開発チームがバグを早期に発見・修正できるようにする必要があります。

🔵 **信頼性レベル**: 青信号（要件定義書 REQ-204、REQ-205、ユーザヒアリング2026-09-12 Q4より確実）

### 達成目標
1. エラーイベント定数の追加（network_error、exception_occurredなど）
2. エラーパラメータ定数の追加（error_type、error_codeなど）
3. Repository層でのエラーハンドリングとイベント記録
4. ViewModel層での例外キャッチとイベント記録
5. PIIフィルタリング（エラーメッセージ除外）の実装とテスト

### 非目標
- Firebase Crashlyticsの導入（別タスクで検討）
- カスタム例外クラスの作成
- エラーログのローカル保存

## 要件定義

### 機能要件（EARS記法）

#### 通常要件 - エラーイベント定数管理

**REQ-0007-001**: システムはエラーイベント名を`AnalyticsEvents`オブジェクトに追加しなければならない
🔵 *REQ-204、REQ-205（要件定義書）、ユーザヒアリング2026-09-12 Q4より*

- イベント名定数（追加）:
  - `NETWORK_ERROR`: ネットワークエラー発生
  - `DATABASE_ERROR`: データベースエラー発生
  - `EXCEPTION_OCCURRED`: 予期しない例外発生
  - `API_ERROR`: API呼び出しエラー
- Firebase Analytics制限に準拠（最大40文字）🔵 *EDGE-102より*

**REQ-0007-002**: システムはエラーパラメータ名を`AnalyticsParams`オブジェクトに追加しなければならない
🔵 *NFR-201（要件定義書）、コーディングベストプラクティスより*

- パラメータ名定数（追加）:
  - `ERROR_TYPE`: エラー種別（ネットワーク、データベース、例外等）
  - `ERROR_CODE`: エラーコード（HTTPステータスコード等）
  - `EXCEPTION_CLASS`: 例外クラス名
  - `REPOSITORY_NAME`: エラー発生Repository名
  - `OPERATION`: エラー発生操作名
- Firebase Analytics制限に準拠（最大40文字）🔵 *EDGE-103より*

#### 通常要件 - PIIフィルタリング

**REQ-0007-003**: システムはエラーメッセージをAnalyticsイベントに含めてはならない
🔵 *NFR-101（要件定義書）、Firebase Analyticsセキュリティガイドラインより*

- エラーメッセージには個人情報（ユーザー名、メールアドレス等）が含まれる可能性がある
- エラー種別、エラーコード、例外クラス名のみ記録
- スタックトレースは記録しない

**REQ-0007-004**: システムはスタックトレースをAnalyticsイベントに含めてはならない

#### 通常要件 - ネットワークエラートラッキング

**REQ-0007-005**: システムはネットワークエラー発生時にイベントを記録しなければならない
🔵 *REQ-204（要件定義書）、ユーザヒアリング2026-09-12 Q4より*

- イベント名: `NETWORK_ERROR`
- パラメータ:
  - `ERROR_TYPE`: "network"

  - `REPOSITORY_NAME`: エラー発生Repository名
  - `OPERATION`: エラー発生操作名（例: "fetchWeather"、"fetchNews"）
  - `TIMESTAMP`: エラー発生時刻

**REQ-0007-006**: システムはAPI呼び出しエラー発生時にイベントを記録しなければならない
🔵 *REQ-204（要件定義書）、既存実装（Retrofit API）より*

- イベント名: `API_ERROR`
- パラメータ:
  - `ERROR_TYPE`: "api"

  - `TIMESTAMP`: エラー発生時刻

3. **AnalyticsErrorLogger.kt**
   - パス: `core/analytics/src/main/java/com/github/takayuki_hub/dashboard/core/analytics/AnalyticsErrorLogger.kt`
   - 責務: エラーロギングのヘルパークラス
   - 参照元: 🔵 REQ-0007-003, REQ-0007-004

```kotlin
package com.github.takayuki_hub.dashboard.core.analytics

import java.time.Instant
import javax.inject.Inject

/**
 * エラーイベント記録のヘルパークラス
 * PIIフィルタリング（エラーメッセージ、スタックトレース除外）を実装
 */
class AnalyticsErrorLogger @Inject constructor(
    private val analyticsRepository: AnalyticsRepository
) {

    /**
     * ネットワークエラーを記録
     * @param errorCode HTTPステータスコード
     * @param repositoryName エラー発生Repository名
     * @param operation エラー発生操作名
     */
    suspend fun logNetworkError(
        errorCode: Int,
        repositoryName: String,
        operation: String
    ) {
        analyticsRepository.logEvent(
            eventName = AnalyticsEvents.NETWORK_ERROR,
            params = mapOf(
                AnalyticsParams.ERROR_TYPE to "network",
                AnalyticsParams.ERROR_CODE to errorCode,
                AnalyticsParams.REPOSITORY_NAME to repositoryName,
                AnalyticsParams.OPERATION to operation,
                AnalyticsParams.TIMESTAMP to Instant.now().toString()
            )
        )
    }

    /**
     * API呼び出しエラーを記録
     * @param errorCode HTTPステータスコード
     * @param repositoryName エラー発生Repository名
     * @param operation API操作名
     */
    suspend fun logApiError(
        errorCode: Int,
        repositoryName: String,
        operation: String
    ) {
        analyticsRepository.logEvent(
            eventName = AnalyticsEvents.API_ERROR,
            params = mapOf(
                AnalyticsParams.ERROR_TYPE to "api",
                AnalyticsParams.ERROR_CODE to errorCode,
                AnalyticsParams.REPOSITORY_NAME to repositoryName,
                AnalyticsParams.OPERATION to operation,
                AnalyticsParams.TIMESTAMP to Instant.now().toString()
            )
        )
    }

    /**
     * データベースエラーを記録
     * @param exception 例外オブジェクト（メッセージは記録しない）
     * @param repositoryName エラー発生Repository名
     * @param operation データベース操作名
     */
    suspend fun logDatabaseError(
        exception: Throwable,
        repositoryName: String,
        operation: String
    ) {
        analyticsRepository.logEvent(
            eventName = AnalyticsEvents.DATABASE_ERROR,
            params = mapOf(
                AnalyticsParams.ERROR_TYPE to "database",
                AnalyticsParams.EXCEPTION_CLASS to (exception::class.simpleName ?: "Unknown"),
                AnalyticsParams.REPOSITORY_NAME to repositoryName,
                AnalyticsParams.OPERATION to operation,
                AnalyticsParams.TIMESTAMP to Instant.now().toString()
            )
        )
    }

    /**
     * 予期しない例外を記録
     * @param exception 例外オブジェクト（メッセージは記録しない）
     * @param source 例外発生場所（Repository名またはScreen名）
     * @param operation 例外発生操作名
     */
    suspend fun logException(
        exception: Throwable,
        source: String,
        operation: String
    ) {
        analyticsRepository.logEvent(
            eventName = AnalyticsEvents.EXCEPTION_OCCURRED,
            params = mapOf(
                AnalyticsParams.ERROR_TYPE to "exception",
                AnalyticsParams.EXCEPTION_CLASS to (exception::class.simpleName ?: "Unknown"),
                AnalyticsParams.REPOSITORY_NAME to source,
                AnalyticsParams.OPERATION to operation,
                AnalyticsParams.TIMESTAMP to Instant.now().toString()
            )
        )
    }
}
```

```kotlin
@Inject
class WeatherRepositoryImpl @Inject constructor(
    private val weatherApi: WeatherApi,
    private val analyticsErrorLogger: AnalyticsErrorLogger
) : WeatherRepository {

    override suspend fun getWeatherData(latitude: Double, longitude: Double): Result<WeatherData> {
        return try {
            val response = weatherApi.getWeather(latitude, longitude)
            if (response.isSuccessful) {
                response.body()?.let {
                    Result.success(it.toWeatherData())
                } ?: Result.failure(Exception("Empty response"))
            } else {
                // ネットワークエラー記録
                analyticsErrorLogger.logNetworkError(
                    errorCode = response.code(),
                    repositoryName = "WeatherRepository",
                    operation = "getWeatherData"
                )
                Result.failure(Exception("HTTP ${response.code()}"))
            }
        } catch (e: Exception) {
            // 例外記録
            analyticsErrorLogger.logException(
                exception = e,
                source = "WeatherRepository",
                operation = "getWeatherData"
            )
            Result.failure(e)
        }
    }
}
```

## エッジケース・考慮事項

### エラーハンドリング

#### 例外クラス名がnull
- **シナリオ**: exception::class.simpleNameがnull（無名クラス等）
- **対応**: nullコアレッシング演算子で"Unknown"を設定
- **影響度**: 低
- **信頼性**: 🔵 実装コードより

#### HTTPステータスコードが範囲外
- **シナリオ**: response.code()が標準範囲外（例: -1）
- **対応**: そのまま記録、Firebase Analytics側でフィルタリング
- **影響度**: 低
- **信頼性**: 🟡 妥当な推測

### パフォーマンス考慮事項

#### エラー発生頻度
- **課題**: ネットワークエラーが連続発生した場合のイベント送信負荷
- **対応**: Firebase Analytics SDKが自動的にバッチング処理
- **影響度**: 低
- **信頼性**: 🔵 Firebase Analytics SDK仕様より

#### Repository層での非同期処理
- **課題**: AnalyticsErrorLoggerがsuspend関数、Repository層でも適切にコルーチンコンテキストで実行
- **対応**: 既存のRepository実装がsuspend関数、そのままコンテキスト継承
- **影響度**: 低
- **信頼性**: 🔵 Kotlin Coroutines仕様より

### セキュリティ考慮事項

#### エラーメッセージのPII
- **課題**: エラーメッセージに「User John Doe not found」等のPIIが含まれる可能性
- **対応**: エラーメッセージを一切記録しない 🔵 *REQ-0007-003より*
- **影響度**: 高

#### スタックトレースのPII
- **課題**: スタックトレースにファイルパス等の内部情報が含まれる
- **対応**: スタックトレースを一切記録しない 🔵 *REQ-0007-004より*
- **影響度**: 高

#### 例外クラス名の露出
- **課題**: 例外クラス名が難読化後も意味を持つか
- **対応**: クラス名は技術的な情報のみ、PIIに該当しない
- **影響度**: 低
- **信頼性**: 🔵 Firebase Analyticsセキュリティガイドラインより
